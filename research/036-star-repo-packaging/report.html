批判的検討

  • 配布系を増やしても順位はほとんど動かない。収録は 17.9% から 36.8% に倍増したが、星側 f_orph は 0.02 しか下がらず、P(S＞T＋C) も 0.43→0.41。理由は、(1) 模型では Homebrew の項が clone の項と同じ a・s_r を共有し、a が小さい組では両方とも小さく、a が大きい組ではどちらか一方で足りること【推測、模型の構造による】、(2) Homebrew の写しはコンパイル済みの本体で欠ける価値 g_b が大きく、install 数も星と同程度（中央値 0.51件／星）しかない。上限の変種でも A_XPT_E では第2拠点が上（0.89〜0.92）。
  • 残る星重みの半分は、配布系にそもそも載らない文章型（広い規則で）。これは package にならないので、補えるかどうかは clone が生き残り見つかる割合 a だけで決まる。a の Spearman は −0.84 のままで、035 と同じく最大の未知。
  • H48b の棄却は主に事前登録の分類規則の誤り（主言語で文章型を絞った）による。探索の広い規則では境界（50.0%）で、どちらとも言えない。
  • Homebrew の集計は opt-out で、事前登録では「任意参加」と書いたが誤りだった（逸脱(1)）。既定で有効なので ι の下限 1 は妥当だが、上限 10 は推測のまま。ι の効きは小さい（Spearman −0.03）。
  • 星重みの母集団は ≥20,000 星の 1,368件だけ。照合は URL に頼り、取りこぼし（名前一致・registry で最大 +26%）がある。上限の変種はこれを含めた。
  • Homebrew の主な利用は macOS で、地域の開発者の割合 s_r を Debian の clone と同じに置いた（推測）。

結論

Debian に Homebrew と nixpkgs を加えると、≥20,000 星の repo の収録は星重みで 18% から 37% に倍増するが、金庫の中身のうち手元の写しで補えない割合（星側）は 0.47 から 0.45 にしか下がらず、第2拠点が束を上回る確率も A_XPT_S で 0.43→0.41、A_XPT_E で 0.94→0.93 とほぼ変わらない。残る星重みの約半分は一覧や教材のように配布系に載らない文章で、補えるかは clone の生き残り a で決まる。配布系の収録を数える作業はここで頭打ちで、次は a を直接見積もるべきである。

この結果を受けて、誰が何を変えるべきか

  • 南半球の第2拠点の運営者（候補の大学・国立図書館）：配布系の写しで代わりがきかない星の上位は、主にソフトでなく一覧・教材・本の repo（build-your-own-x、public-apis、free-programming-books、system-design-primer、coding-interview-university など）なので、これらを最初に置く。容量は小さい（文章が中心）。
  • 本研究所：f_orph の星側は 035 の 0.47 を 0.45（上限の変種で 0.30〜0.37）に置き直す。配布系の照合による改善はこれ以上追わず、a（open_problems 106）を次の主課題にする。

既存研究に対する新規性

035 は Debian だけを測った。本研究は Homebrew の 365日の install 数（観測された写しの数）と nixpkgs を加え、配布系を増やしても金庫の第2拠点の順位がほぼ動かないこと、補えない星重みの約半分が配布系に載らない文章型であることを示した。確認した資料（Ord、XPT、Software Heritage、GitHub Archive Program、Debian、Homebrew Analytics）には、人気の repo の配布系での収録を崩壊後の知識保存の評価につなげたものは見当たらない。
