問い

025 は「展開に要る RAM = 16 KiB + min(8 MiB, TAR)」として、1950年代前半級（4〜144 KiB）の読者の q を約0.04 とした。窓を高速 RAM ではなくドラム・ディスク・テープに置けば RAM の壁は消えるはずで、そのとき壁は「時間」になるのか「補助記憶の容量」になるのかを、実 repo の LZMA 参照距離から決める。

事実入力（本回開いて確認、sources/ に写し）

  • 【事実（IBM 650）】ドラム 12,500 rpm・1回転 4.8 ms・非最適化の平均アクセス 2.5 ms、1バンド50語・1語5文字、4000語 ≈35 KB。
  • 【事実（Drum memory）】UNIVAC File Computer のドラム1台 180,000×6ビット文字（135 KB）。

結論

025 の「RAM の壁」は、本当は「ランダムアクセスできる記憶の容量の壁」だった。窓をドラムに置けば時間はほとんど増えず（CPU の約3%）、ディスクでも約2倍で、CPU そのもの（1 MB あたり約20分、高層全体で約150機械年）が時間の上限を決める。代わりに、8 MiB の窓を置くには 1950年代のドラムなら63〜240台、IBM 350 級のディスクなら3台が要る。手引きから作る読取装置が届ける価値は、RAM の大きさではなく、作れるランダムアクセス記憶の容量でほぼ決まり、135 KB のドラム1台では 025 とほとんど変わらない（ΔV 0.013）。一方、テープに窓を置く方法は容量の制約がほぼなく、遅いが星重みで約半分（ΔV 0.089、024 の値と同程度）に届くので、手引きの現実的な代替路になりうる【推測】。

誰が何を変えるべきか

  • 読取装置の製作手引き（024 の板）を書く人：RAM を増やす章より先に、「窓をテープに置いて復号する手順」（2台のテープ装置で過去の出力を巻き戻して読む方法）と、ディスク級（MB 級）のランダムアクセス記憶の作り方を入れる。RAM は 20 KiB（状態 16 KiB＋ブロック置き場 4 KiB）あれば足りることを明記する。
  • アーカイブ運営者：025 の提言（重要 repo を辞書 ≤64 KiB で別に書く）は維持する。辞書を小さくすれば補助記憶そのものが要らなくなり、この回で見た容量の壁を運営者の側で消せる。索引に「展開に要る窓の大きさ」を書く提言も同じ。

既存研究に対する新規性

025 までは「展開に要る RAM」だけを見ていた。本回は、実 repo の LZMA 参照距離を参照復号器で直接数え、窓を遅い記憶に置いたときの時間を1950年代の実機の数値で見積もった。その結果、壁は時間ではなく容量であり、容量の壁はテープか小さい辞書で回避できることを数値で示した。LZMA の参照距離の分布を「崩壊後の読取装置」の設計に結びつけた先行研究は見当たらない【推測：網羅的な検索はしていない】。
