研究031：高層の外にある依存の重みは 2020 年のスナップショットに入ったか（open_problems 93）

事前登録：PREREGISTRATION.md（2026-10-17T08:39:35Z、GitHub の照会の前）。 データ：collect.py（GitHub GraphQL、gh の認証・読み取りのみ、08:40〜08:50 UTC、4,655件を50件ずつ、失敗0、見つからず46）→ data/lowtier_gh.jsonl。解析：sim.py（約14秒、seed 20261031、030 の sim.py を runpy で再利用。030 の図は読み込み前のバイト列で書き戻す）→ results.json、stdout.txt、fig_inclusion_shares.png、fig_budget_dV_U.png。 再現：024〜030 を /tmp/rep031/ に複製し、030 の sim.py・explore.py を再実行（results.json 730キー、explore_results.json 145キー、runtime 以外差分0）。031 も /tmp/rep031b/ で再実行し差分0（590キー）。030 の図の MD5 は変わっていない。 検証：sim.py の中で 030 の高層だけの値を再計算し、収蔵のままの q 0.07517、0.003 リールの q 増分 0.59245 が 030 と完全に一致した。

問い

030 では、D1（repo に結びつく package の最大の依存 repo 数）≥10,000 の GitHub repo の依存重みのうち、高層（現在の星 ≥250、2020-02-02 以前作成、fork でない）に入るのは 43% だけだった。残りの repo は Arctic Vault の低層の条件で実際に収蔵されたのか。低層を含めると、収蔵割合、収蔵のままの q、小窓版の選び方はどう変わるか。

事実入力（本回開いて確認、sources/）

  • 【事実（Arctic Vault のページ、sources/arctic_vault_2026-10-17b.html）】2020-02-02 のスナップショットは、11月13日から 2020-02-02 までにコミットのある全 repo、星 ≥1 で直前1年にコミットのある repo、星 ≥250 の全 repo を含む。既定ブランチの HEAD で、100 KB を超えるバイナリは除く（星 ≥250 の repo は残す）。
  • 【事実（GUIDE.md、sources/github_archive_GUIDE_2026-10-17.md）】収蔵は最後のコミットの時刻と星の数だけで決めた。条件は「直前80日のコミット」「星 ≥1 かつ直前365日のコミット」「星 ≥250」。

方法

  • 対象：030 の全数リストのうち D1 ≥10,000 で高層の外にある repo。030 で未照会（ecosyste.ms の星 <150）4,015件、星 150〜249 の 587件、fork 53件を GraphQL で照会した。030 の照会で作成日 ≥2020-02-02 だった repo と見つからなかった repo は未収蔵として加えた。改名で重なるものと高層の名前を除いて 低層 4,951件。
  • 各 repo の既定ブランチで、2020-02-02T00:00Z より前の最後のコミットの committedDate（LC）を取った。
  • 規則（主）：A（LC ≥ 2019-11-13）または B（LC ≥ 2019-02-02 かつ現在の星 ≥1）。下限は A のみ。上限は A または LC ≥ 2019-02-02（星を問わない）。fork は主では未収蔵、感度で同じ規則を当てた。
  • 母集団 U：030 の高層の母集団（T=10,000）＋低層 4,951件。未収蔵の repo は収蔵のままでは読めない（必要 RAM を無限大とした）。低層の TAR は 030 の無作為150件の実測回帰（log TAR = 2.38 + 0.736·log 大きさ、残差 SD 0.96）に残差を復元抽出して付けた。読者 B、ΔV の式（024）、c4（4 KiB 辞書・lc0）の費用は 028〜030 と同じ。
  • 予算つき欲張り選択（依存重み）：S-030（030 と同じく高層からのみ）、S-snap（収蔵済みの repo からのみ。スナップショットから書き直す運営者）、S-new（U 全体から。今の GitHub から新しく取る運営者）。

主要結果

  • 【独自計測】低層の依存重みの内訳（主規則）：A（80日以内にコミット）20.1%、B（1年以内＋星）34.3%、最後のコミットが 2019-02-02 より前 35.3%、作成日が 2020-02-02 以降 6.7%、fork 2.5%、見つからず 1.1%。収蔵されたのは 54.3%（2,179件）。
  • 【独自計測】依存の上位の小さな部品のうち、更新が止まって「完成」していたものは入っていない。例：isaacs/fs.realpath（D1 553万、星 25、最後のコミット 2016-06-15）、stream-utils/unpipe（505万、2018-06-29）、jaredhanson/utils-merge（495万、2018-10-15）、stream-utils/destroy（452万、2018-10-23）。一方、jonschlinkert/fill-range（546万、2019-06-17）や jshttp/fresh（502万、2019-04-11）は規則 B で入った。低層の依存重みの最後のコミット年は 2019 年が45%、2018 年以前が計36%。

逸脱

  • 事前登録では規則 B の星を「最初の星の日付」（stargazers の starredAt）で判定する予定だった。照会してみると、GraphQL の stargazers は星 23,327 の chalk/chalk でも totalCount 0 を返し、REST の stargazers は 404 だった（2026-10-17 時点）。最初の星の日付は1件も取れなかった（0/4,609）。照会の後・解析の前に、主規則の B を「現在の星 ≥1」に置き換えた。現在の星が0の repo は10件（低層の依存重みの0.02%）だけなので、主規則は事前登録の上限とほぼ同じになった。
  • H43f の「ΔV の90%」は、収蔵のままの ΔV（0.031）からの増分の90%として判定した。絶対値の90%（0.213）でも、0.003 リールの S-new（0.218）が超えている。

批判的検討（限界）

  • 規則 B の判定は「2020 年に星 ≥1 だった」に依存し、それは確かめられていない。下限（A のみ）では低層の収蔵は20%、U の収蔵割合は55%まで下がる。ただし、最後のコミットが 2019-02-02 より前の35%は、星の数によらず（星 <250 である限り）未収蔵と確定している【推測：2020 年の星も 250 未満だったと仮定】。
  • LC は現在の既定ブランチの履歴から取った。2020 年当時の既定ブランチの別のブランチへのコミット、後の履歴の書き換え、コミットの日付と push の日付のずれは見ていない。GitHub がどの時刻で「コミット」を判定したかは公開文書に書かれていない。
  • 星 <250 の判定は現在の星。2020 年に星 ≥250 で、その後に減った repo は見落とす（少ないと考えられる【推測】）。
  • D1 は 2026 年の値。2020 年以降に作られた repo（低層の依存重みの6.7%）はスナップショットに入りようがないので、「未収蔵」の一部はスナップショットの欠点ではなく、時代の差である。
  • U には高層の外で D1 <10,000 の repo を入れていない。低層の重みは下側に偏る。
  • Arctic Vault の実際の目録（reel の索引）とは照合していない。

結論

Arctic Vault の公開された収蔵条件を、依存数の大きい GitHub repo の最後のコミットの日付に当てると、高層の外にある依存重みの約54%（星の条件が確かめられないため下限20%）は低層として収蔵されていた。残りの大半は、2019-02-02 より前に更新が止まった小さな npm 部品（fs.realpath、unpipe、utils-merge、destroy など）で、星 250 未満のため入っていない。低層を含む母集団では、依存重みの約4分の1がスナップショットの外にある。スナップショットから書き直すだけの小窓版は、今の GitHub から取って書く場合の69%しか得られない。今の GitHub から取れば、0.003 リール（約 340 MB）で、全体を小窓版で書く場合の ΔV の約9割を得る。

誰が何を変えるべきか

  • アーカイブ運営者（GitHub Archive Program・Piql）と Tech Tree の索引担当：次の書き込みでは、スナップショットの規則（最後のコミットの時刻と星）とは別に、パッケージ管理系の依存数の上位を「最後の更新の日付を問わず」収める枠を作る。最初の 0.003 リールには、依存数の上位約5,900件を今の GitHub から取って小窓版（dict=4KiB,lc=0）で書く。そのうち約2,300件は 2020 年のスナップショットに入っていない。030 の「高層からの上位約2,200件」の提言はこれで置き換える（U で評価すると 2.3倍）。
  • 本研究所：今後の q の評価は高層だけでなく U（低層を含む母集団）で行う。

既存研究に対する新規性

Arctic Vault の公開資料は収蔵の規則を示すだけで、依存数の大きい部品がどれだけ規則から漏れたかは示していない。本回は、依存数の上位約5,000件の GitHub repo の最後のコミットの日付に公開された規則を当て、漏れた依存重みの割合（低層の約46%、U 全体の約26%）と、その漏れを埋める費用（0.003 リール程度）を初めて数値で出した。030 までの「高層だけ」の評価は、選び方の価値を2倍以上低く見ていた。
